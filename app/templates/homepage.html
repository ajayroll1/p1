05 / Runtime

Gunicorn + systemd + Nginx

The application process stays private while Nginx is the public HTTP entry point.

Gunicorn

WSGI application server bound to 127.0.0.1:8000.

systemd

p1.service keeps Gunicorn running and starts it on boot.

Nginx

Accepts public traffic, forwards requests and serves collected static files.

06 / Commands

How it was done

A compact command trail from local setup to the running Azure server.

# Local python -m venv .venv .\.venv\Scripts\Activate.ps1 python -m pip install django django-admin startproject project . python manage.py startapp app python manage.py migrate python manage.py runserver # Git git add . git commit -m "feat: update Django showcase" git push origin main
# Azure sudo apt update sudo apt install -y nginx python3 -m venv .venv source .venv/bin/activate pip install -r requirements.txt pip install gunicorn python manage.py check python manage.py collectstatic --noinput sudo systemctl enable p1 sudo systemctl start p1 sudo nginx -t sudo systemctl reload nginx

Static files

Production uses STATIC_URL="/static/" with STATIC_ROOT = BASE_DIR / "staticfiles", followed by collectstatic and Nginx serving the collected files.
